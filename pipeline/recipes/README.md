# Recipes

Generated by `python tools/recipes_index.py` from the header of every recipe file. Do not edit: change the header.

A recipe is one small script for one kind of grip or weapon. It runs on the merged clip in the prop step of
`pipeline/chain.py` and of `character.py`'s merge stage. The motion file names it and holds its inputs:
`"recipe": {"name": "<name>", ...}`, or a list of such entries run in that order, each on the file the one
before it wrote (a recipe that measures the result goes last). Choose them once, when writing the motion file.
A name outside this list is a schema error. `prop_in_hands` is the one exception: experimental, frozen, selected
by `actions.<a>.prop: true`.

Read the row, then the file's header for `Inputs`, `Output` and `Checks`. Nothing fits: copy the smallest recipe
into a new file, give it this header and its own rules; do not add a switch to an existing one.

| Recipe | What | Use when | Not for |
|---|---|---|---|
| `one_hand_weapon` | One-handed weapon carried rigidly in one hand: sword, axe, mace, torch. | one hand holds the weapon by its grip through the whole action and the other hand never touches it; the approved pose scene already shows where the weapon sits in that hand. | two-handed grips, a weapon that changes hands or is drawn, thrown or sheathed, a shield strapped to the forearm, a grip that slides along the shaft. |
| `prop_in_hands` | Two-handed prop solver - EXPERIMENTAL and frozen: it gets no further rounds, a new grip is a recipe in pipeline/recipes/. | both hands hold one long prop that the rig carries on its own bone (crossbow, rifle, two-handed staff) and the action is a hold, an aim or a shot; expect to review every frame. | a one-handed weapon (one_hand_weapon), a prop that is not part of the rig, anything that must pass the audit unattended: on the crossbowman it leaves the stock 4-5 cm in the upper arm, snaps into and out of the armpit in one frame, lifts the elbow over the stock and leaves fingertips up to 5 cm off it; its fix passes do not converge. |
| `swing_arm` | One-handed swing: keep the weapon's path, solve the arm that holds it again. | the weapon's path through the clip is accepted but the arm holding it is wrung: the upper arm turned about its own axis, the elbow up beside the shoulder, the forearm rolled over. List it before `one_hand_weapon` in `recipe`. | a path that is itself wrong (the path is kept; `path_edits` only tilt or move it on named frames), two-handed grips, a rig whose arm bones do not point at the next joint, an arm that never bends in the clip. |

## Writing one

- One file `pipeline/recipes/<name>.py`; the docstring starts with a title line, then `Use when:`, `Not for:`,
  `Inputs:`, `Output:`, `Checks:` in this order, one or two lines each, for a reader who has not seen the code.
- Arguments `--glb <merged> --motion <motion file> --out <glb> [--skeleton X]`; success is a printed line
  `RECIPE OK <out>`. It keys only the action named by the motion file and says in `Output` which bones it moves.
- It writes `<out>_recipe.json` with `recipe`, `action`, `line` (one sentence of what it measured), `limits` (what
  the measurement misses) and its own numbers. The audit copies it into `audit.json` and prints `line`; not scored.
- Rules that need no Blender are functions above `main()`, tested on synthetic data in `tests/`; `bpy` is imported
  inside `main()` so the tests can import the file.
- In a list it reads its own entry (`recipe_list.entry(motion, NAME)`) and may read another recipe's inputs from
  theirs; it never runs another recipe. A second step for an existing case is a new recipe, not a switch.
- Add the name and its inputs to `$defs.recipe` in `schemas/motion.schema.json`, then run
  `python tools/recipes_index.py`. `tests/test_recipes.py` fails on a stale index, a missing header or a name the
  schema does not list.
